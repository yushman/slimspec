slimspec
GitHub English

Сильным моделям не нужны тяжёлые спеки.

Агент сам восстанавливает картину, быстро пробежав по коду. Спеке остаётся подсказать ему, что делать и где искать. А explore уже и есть спека изменения.

slimspec — плагин для Claude Code, построенный на этой идее. Он запускает цикл explore → plan → apply → verify с обязательным red-green TDD. На изменение заводятся два временных файла. У каждого модуля одна компактная спека во вложенном CLAUDE.md, который Claude Code подгружает автоматически: где искать и что нельзя сломать, и ничего больше.

/plugin marketplace add yushman/slimspec
/plugin install slimspec@slimspec
Репозиторий на GitHub Дальше: /slimspec <идея>

Замеры на реальном проекте

Миграция

Один существующий проект, просмотрщик логов на Rust с веб-интерфейсом, перевели с OpenSpec командой /slimspec:migrate-openspec. До и после:

OpenSpecslimspec
Спеки поведения23 файла, 2 941 строка, ~155 КБ3 файла, 484 строки, ~34 КБ
Архив изменений23 изменения, 12 394 строки, ~733 КБ0
Корневой CLAUDE.md130 строк121 строка
Файлов в openspec/2000

Откуда разница

  • Сценарии WHEN/THEN влились в требования, которые они и описывали. Пустые разделы Purpose и шаблонные SHALL ушли.
  • Одна спека на модуль вместо 23 на фичи. Агент читает только спеку модуля, в котором работает: правка в web/ подтягивает ~11 КБ, а не россыпь capability-файлов по всему дереву.
  • Архива изменений в рабочем дереве больше нет. В git-истории того проекта он остался.

Что потеряно

  • Сценариев как списка тест-кейсов больше нет.
  • Обоснования отдельных изменений пропали. Часть сохранилась в ADR, остальное есть только в git-истории.
  • Самая большая спека модуля (~14 КБ) грузится целиком при любой работе в этом модуле.

Спустя четыре изменения на slimspec спеки модулей — 4 файла и 641 строка, всё ещё на 78% меньше спек OpenSpec, которые они заменили.

Стоимость изменения

Тот же проект до и после миграции, замер по транскриптам Claude Code. Токены — весь вход, который обработала модель (input + чтение кэша + запись в кэш), основная сессия и субагенты вместе. Самая близкая по размеру пара:

OpenSpec (logcat-padded-tags)slimspec full (iana-tz-hash)
Изменено кода409 строк, 4 файла, один модуль435 строк, 15 файлов, три модуля
Обработано токенов45,7M29,7M (−35%)
Токенов на строку кода~110k~68k (−38%)
Ревьюнет2 раунда verify на глубине high; один реальный блокер (паника на крайних датах) исправлен внутри изменения
Закоммичено процессных файлов~530 строк (proposal, design, tasks, дельты спек, devlog)0 (папка изменения удалена; правки спек — в CLAUDE.md модулей)
Время от начала до конца, с гейтами91 мин56 мин

При этом slimspec сделал больше: 5 вопросов по решениям и 3 гейта, 9 задач в 3 волнах, ground в 4 спеки, ADR и оба README.

Мелкие изменения показывают то же. Два изменения на OpenSpec обработали 31,5M и 45,7M токенов; два на slimspec (fast и medium) — 6,8M и 12,5M. Один implementer в OpenSpec в одиночку обрабатывал 13–16M токенов, субагент slimspec — 0–1M, потому что каждому достаётся одна узкая дорожка.

Оговорки: n = 1–2 на подход, один проект. Мелкие изменения на slimspec были в 5–10 раз меньше по коду, так что часть разницы — размер. Часть агентов slimspec работала на Sonnet или Haiku. Основная сессия прогона slimspec full несла посторонний контекст из более ранней работы, что завышает её счёт.

Как идёт работа

explore
Агент-сканер читает спеки модулей, потом код, и возвращает короткую сводку. Основная сессия задаёт вам вопросы (одно решение на вопрос, независимые вместе) и пишет explore.md. К плану сама не переходит.
plan
Планировщик пишет tasks.md волнами и делит каждую волну на дорожки из связанных задач. Дорожки одной волны трогают непересекающиеся файлы и идут параллельно. У каждой задачи указан первый падающий тест.
apply
На каждую дорожку свой исполнитель: он проходит её задачи по порядку и по каждой приносит доказательства red и green. Полный набор тестов гоняется после каждой волны.
verify
Ревьюер сверяет результат с планом и дизайном, проверяет доказательства TDD и сам код. Баги уходят обратно в apply, вопросы к дизайну приходят к вам через refine.
ground
Из изменения выделяются долговременные знания (поведение, инварианты, контракты, решения), и модель вливает их в спеки затронутых модулей. Поиск по ключевым словам для слияния не используется. После этого папка изменения удаляется.

Остановок две: после explore и после plan. Каждая остановка начинается с подробного разбора: после explore показывается дизайн с диаграммами, после plan показывается полный план (волны, дорожки, тесты по задачам). Остальные фазы идут без остановок и возвращаются к вам только с вопросами агентов, замечаниями к дизайну или после двух автоматических циклов исправлений.

Все решения принимает основная сессия. Субагенты выполняют работу и возвращают короткий структурированный отчёт: статус, файлы, решения, отступления от плана, red/green. Напрямую они вас ни о чём не спрашивают. Открытый вопрос возвращается как BLOCKED, основная сессия задаёт его вам и перезапускает агента с ответом.

Изменение живёт в .slimspec/changes/<slug>/: это explore.md и tasks.md. Папка в .gitignore и удаляется после ground. Историю хранят ваши коммиты и обновлённые спеки.

slimspec использует части обоих инструментов. В таблице перечислено только то, в чём slimspec отличается; жирным в колонке slimspec выделено, в чём он лучше.

Замеренная стоимость45,7M токенов на изменение ~400 строкне замерялась29,7M токенов на сопоставимое изменение, с двумя раундами ревью

Чего нет в slimspec. У OpenSpec сценарии остаются явными тест-кейсами, рядом со спеками лежит полная история всех изменений, и он работает с 30+ AI-инструментами. В Superpowers есть скиллы помимо работы со спеками (отладка, worktree, код-ревью и другие), и он поддерживает многих агентов. slimspec работает только с Claude Code и покрывает только spec-driven цикл.

Переезд с OpenSpec или Superpowers

/slimspec:migrate-openspec     # openspec/specs/ → спеки модулей
/slimspec:migrate-superpowers  # дизайн-документы Superpowers → спеки модулей
  • Переносятся только спеки. Каждая спека источника привязывается к модулям, сжимается в ваш spec.format и сверяется с кодом.
  • Сначала вы подтверждаете таблицу «источник → спека» и решаете по каждому утверждению, с которым расходится код.
  • Изменения, планы и служебные файлы не конвертируются. Удаляются они только на финальном шаге очистки и только то, что вы подтвердите. Код не трогается.
  • Сам плагин Superpowers удаляется через /plugin uninstall.

Конфиг

Конфиг необязателен: у каждого ключа есть значение по умолчанию. /slimspec:init задаёт несколько вопросов в сессии и записывает .slimspec/config.yaml:

mode: medium              # fast | medium | full
spec:
  format: claude-md       # claude-md | readme | central | native | none
  unit: auto              # auto (по билд-файлам) | glob директорий, напр. "src/*/"
  adr: false              # дополнительно вести решения в docs/adr/NNNN-*.md
test: auto                # или явная команда
commit: none              # none | lane | wave
apply:
  agents: 3               # максимум параллельных implementer = максимум дорожек в волне
review:
  depth: auto             # auto (по режиму) | low | medium | high
models: {}                # переопределения по ролям

Модели по умолчанию: scanner и implementer на sonnet, planner, reviewer и grounder на opus. slimspec никогда не пушит.
